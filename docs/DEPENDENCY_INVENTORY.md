## Findings

1. **Lockfile now committed** on the work branch; generated by npm 10.9.9 on Node 22.23.3 using `npm install --package-lock-only --ignore-scripts`, not hand-authored.
2. CI installation has been changed to `npm ci`, which enforces the committed lockfile rather than resolving package ranges from scratch.
3. The lockfile-generation run reported 0 npm audit vulnerabilities for its resolved tree. This is an npm registry advisory result at that run's time, not a complete license audit or proof of zero security risk.
4. `better-sqlite3` is a native addon. Packaging must validate the actual Node/Electron ABI and target OS/CPU combinations; the manifest is not sufficient evidence of cross-platform readiness.
5. License/notice review and Electron native-addon packaging tests remain outstanding; no new extraction package is approved by this inventory.

## Required next steps before approving dependencies

- Generate and commit a lockfile through a real npm install in a controlled checkout; do not hand-author one.
- Switch CI to `npm ci` after the lockfile is committed, then confirm a clean install and all checks.
- Produce a license and advisory inventory from the resolved dependency tree (including transitive packages) and record the native build/runtime matrix.
- Keep PDF, DOCX, XLSX, OCR, embedding, and vector-search libraries unselected until their exact versions pass representative fixture, security, fidelity, license, and packaging gates.
